# 非遗跨境展演知识边界

围绕「知识许可包」整理非遗跨境展演场景中的事件名称、交换字段、脱敏样例与领域服务，
方便业务、运营和研发人员在同一套术语下讨论。资料只包含领域约定与虚构数据，
不包含真实个人信息、生产连接或外部账号。

## 场景

海外合作方把只获准现场讲解的口述资料放进宣传册，传承人要求停止扩散。项目组需要：

- 记录来源的贡献者、敏感等级、可用地域与用途；
- 让译文按语言、审校意见与「纠正取代」关系演进；
- 发行时固定本次采用的来源条款、译文、用途、接收机构与失效条件；
- 接收方回执可离线乱序到达，按**使用时点**而不是到达时点判定；
- 条款变化、贡献者撤回、译文更正只作用于尚未发生的使用，过去合规的履约保留可审计；
- 单个机构投递失败不回滚其余机构；恢复后继续处理待确认与到期停用，通知不重复；
- 从一笔海外宣传用途反查：当时用了哪版译文、谁批准了什么范围、后续为何被限制。

## 目录

- `src/heritage_exchange_boundary.js`：事件种类、敏感等级、处置原因与字段校验（领域约定）。
- `src/event_store.js`：仅追加事件存储（内存版与 JSONL 持久版），流版本并发与命令幂等。
- `src/license_pack.js`：知识许可包领域服务（投影、时点判定、发件箱、停用扫描、反查）。
- `data/sample.json`：用于核对资料格式的虚构事件。
- `tests/`：领域约定一致性与许可包全场景测试。

## 模型与保证

### 事件溯源，只追加

所有状态变化都是不可变事件；撤回、条款变更、译文更正都不删除或改写历史，
只追加新事件。投影按事件重放重建当前状态，任何时点的判定都可复核。
已合规的履约（`USE_ACKNOWLEDGED`）因此始终保留、可审计。

### 时点有效性

授权是否合规一律按回执申报的 `used_at` 判定：

| 判定 | 规则 |
| --- | --- |
| 来源条款 | 取 `effective_from <= used_at` 的最近一版；条款收紧只影响之后的使用 |
| 贡献者撤回 | 撤回 `effective_from <= used_at` 才使该使用违规 |
| 译文版本 | 使用时点须为已批准且未被更正版本取代 |
| 授权状态 | 使用时点该机构已成功投递、未撤回/到期/条款停用 |
| 用途与地域 | 必须与发行快照一致 |
| 项目归属 | 回执 `project_id` 必须与许可包一致，许可不可跨项目迁移 |
| 失效时间 | `used_at > expires_at` 即超期 |

违规回执进入 `USE_DISPOSITION_ENTERED`（原因见 `DISPOSITION_REASONS`），并产生处置通知。
迟到的旧确认若合规仍被确认，但标记 `stale`，**不覆盖**当前的停用/撤回状态。

### 发行快照

`PACKAGE_ISSUED` 固定 `terms_snapshot`（当时生效条款）、译文版本、用途、地域、
项目、接收机构、失效时间与批准人，构成不可变的授权基线。

### 投递部分失败

投递按机构逐条记录 `GRANT_DELIVERED` / `GRANT_DELIVERY_FAILED`。一个机构失败
只产生该机构的失败事件与后续处置，其余机构状态不受影响，没有整体回滚。

### 离线乱序回执

- `receipt_id` 幂等：同一回执重复/乱序重投返回首次结论，不追加事件（索引从事件流重建，重启后仍有效）。
- 回执与结论在同一提交批次落盘；崩溃未提交的批次由离线通道重投补齐。

### 停用扫描与崩溃恢复

`sweepRestrictions()` 扫描应停用而未停用的授权（撤回、到期、条款收紧），
逐包独立提交，可在恢复后反复运行而不重复停用。

`dispatchNotifications()` 是事务发件箱：只发送 `NOTIFICATION_DUE` 中尚无
`NOTIFICATION_SENT` 的通知，发送携带 `dedupe_key`，通道据此去重；
发送成功才记录已发送，崩溃后只补未记录的，对外不重不漏。

JSONL 存储中**一批事件序列化为日志一行**：崩溃最多丢失最后一个未提交批次，
不会留下跨行半成品。

### 审计反查

`traceUse(pack_id, recipient, used_at)` 一次返回：当时译文版本与审校意见、
批准人与批准范围、来源贡献者与使用时点敏感等级、投递记录，以及该使用之后
发生的条款变更、撤回、译文更正与授权停用。
